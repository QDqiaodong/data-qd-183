# 离线复盘播放器字幕质检 v1（subtitle-playback-qc）

`subtitle-playback-qc --source INPUT.json --output REPORT.json` 是独立离线命令，把一次采集中播放器的时钟表和显示日志同普通模式实际交付的 SRT 对账：按日志批次的到达顺序逐步重建可信显示状态，在已知区间内比较应显示与实显示的行号集合，为每一批输出要撤回/要加入的完整告警行与三项时长的有符号差值。质检台从「整段未知」的初始视图开始，只逐批回放这些更正即可得到该批的规范告警和计量，不需要读取后续批次或全量重载。它不读取媒体文件，不改变 `subtitle-conform`、`--broadcast`、`--carry-review` 与 `cut-clearance` 的行为；输入解析、8 MB 上限、重复键/非有限常量拒绝、严格字段与原子新建报告的语义与其他命令一致，非法输入或目标已存在时退出 2 且不覆盖已有目标。

## 输入契约

根对象严格只含 `conform`、`capture_end_ms`、`last_seq`、`clock`、`batches` 五个字段，针对一次采集。

- `conform`：普通 `subtitle-conform` 输入对象，按普通模式对版并生成 SRT，规则不变。播放器记录的字幕身份是该 SRT 中实际交付条目的行号，从 1 开始；舍入后零长被丢弃的碎片没有行号。同文不同号不能互相替代。
- `capture_end_ms`：采集时长，1..86400000 的整数。采集时钟以实际经过的毫秒计，区间为 `[0, capture_end_ms]`。采集时长不能用节目时长替代，同一节目段看两次就是两次暴露。
- `last_seq`：采集端确定的最终序号，1..2000 的整数，不是目前收到的最大序号。
- `clock`：播放器另行完整导出的时钟表，1..20 行，按顺序严密覆盖整个采集区间：首行 `start_ms` 必须为 0，相邻行首尾相接，末行 `end_ms` 必须等于 `capture_end_ms`，每段正长。每行字段：
  - `start_ms`、`end_ms`：整数，半开采集区间 `[start_ms, end_ms)`；
  - `program_start_ms`：整数，该段起点的节目位置；
  - `rate_num`/`rate_den`：整数倍速，`rate_num` 0..1000（0 表示暂停），`rate_den` 1..1000。段内节目位置 `p(t) = program_start_ms + (t - start_ms) * rate_num / rate_den`，按精确有理数推进；
  - 每段的节目起点和按速率推到右端的节目位置都必须在普通对版的精确节目范围 `[0, 节目时长]` 内（可等于节目末端）。段间允许回拖或快跳，不为跳过的位置记时；暂停时仍按所在位置计算应显示哪些行；节目末端没有应显示字幕。
- `batches`：1..12 批，每批为日志数组（可为空，每批至多 10000 条），报告按批的到达顺序逐批计算，每一步只使用截至该批收到的记录。数组内部的传输顺序没有业务含义。日志记录字段：
  - `seq`：整数，1..`last_seq`；
  - `at_ms`：整数，0..`capture_end_ms`（含末端）；
  - `op`：`snapshot` 附 `active`（当时屏上完整的行号数组，不得有重复行号，顺序不影响相同判断）；`show`/`hide` 附 `cue`（单个行号），分别加入或移出集合，即便此前已经是该状态也合法；
  - 行号必须对应实际交付的 SRT 行（1..行数），否则为无效行号。

记录级规则：相同序号相同内容属于重发，只算一次；同序号不同内容是输入错误。不同序号的记录按序号排列后时刻不得倒退，包括补包后。若收到第 1 条（`seq` 为 1），它必须是时刻 0 的完整快照。同一时刻的记录按序号应用，用这一时刻所有相关动作之后的状态度量后续时间，不产生正长的中间状态。采集末端的日志可用于确认是否收齐，但在末端发生的动作本身不产生显示时长。

未知字段、布尔值冒充整数、无效行号、非法时钟覆盖、快照重复行号、冲突重发、时刻倒退等均为输入错误；输入任一批有错误则整份输入失败。

## 可信状态规则

对任一批后的已收记录，按以下规则判断哪些采集时间的显示状态可信（未知是保守估计，不等于屏上没有字幕）：

1. 没有记录时整段未知；首次完整快照前的显示状态为未知。
2. 两个已收记录之间若跳了序号，从前一条记录的时刻起就无法保证显示状态；下一条是单行增减也不能恢复可信状态，只有收到的完整快照可以让其后的状态重新可信。
3. 最后收到的序号小于 `last_seq` 时，从最后收到的记录时刻起也不可信。
4. 序号缺口若夹在同一时刻的记录之间，不单独制造正长区间，但它破坏对后续状态的信任，除非被其后的快照重建；快照与缺口起点同一时刻时，按它们在序号上的先后判断。
5. 补齐缺包后，按同样规则重新判断哪些时间可以对账，不能只把迟到的动作追加到当前屏幕状态上。

## 对账规则

应显示集合：SRT 整数区间按半开 `[srt_start_ms, srt_end_ms)` 使用，命中即该行应显示；条目重叠时预期显示集合包含全部命中的行号。从节目位置换回采集时间用精确有理数，不再舍入。节目末端（位置等于节目时长）没有应显示字幕。

在已知区间内，比较该时刻应显示和实显示的行号集合，分别找出漏显（应显示而未显示）和多显（显示了不应显示）；同一时刻可同时出现两者。告警行使用采集时间，分两类：

- `unknown`：未知区间；
- `mismatch`：已知但不匹配的区间，附升序的 `missing`（漏显）、`extra`（多显）行号数组。

相邻未知合成一行；相邻已知不匹配且两组差异相同的也合成一行；完全匹配不生成告警；只输出正长区间。

计量三项：未知总时长、有任一漏显的已知总时长、有任一多显的已知总时长。同一类每毫秒只计一次；同一毫秒可以分别计入漏显和多显，未知时间不进入二者。时长及告警端点使用精确有理数字符串（如 `600`、`500/3`）。

## 报告契约

原子新建单个 JSON 报告，字段：

- `schema_version`（1）、`mode`（`"subtitle-playback-qc"`）；
- `capture_duration_ms`、`program_duration_ms`：采集时长与精确节目时长字符串；
- `last_seq`：原样回显；
- `line_map`：行号对照，每项含 `line`（从 1 开始）、`fragment_id`（普通对版碎片身份 `[clip_id, cue_id]`）、整数 `srt_start_ms`/`srt_end_ms`；
- `initial_view`：初始视图，即「整段未知」的一条告警与未知时长等于采集时长、另外两项为零的计量；
- `batches`：按到达顺序逐批给出：
  - `batch`、`new_records`（该批新增的不同序号记录数）、`received_records`（截至该批的不同序号记录总数）；
  - `corrections`：相对紧邻前一批（首批相对初始视图）的更正——`withdraw` 为要撤回的完整旧告警行，`add` 为要加入的完整新告警行，`delta` 为三项时长的有符号差值（精确有理数字符串，正数不带前导加号）。完全相同的行不撤回也不加入；同一起点的行若边界或内容改变，先撤回旧行再加入新行；两份列表各自按数值时间排序；
  - `alerts`、`measurements`：该批之后的规范告警与计量；
- `alerts`、`measurements`：所有批次之后的完整告警和计量，供人工核对；
- `summary`：批次数、已收记录数、最终告警行数与三项最终时长。

## 失败约定

源文件超过 8 MB、含重复 JSON 键、非有限 JSON 常量、根对象非对象或任何字段/引用/记录非法时退出 2，不写报告；输出目标已存在时退出 2 并保留旧文件，不产生临时残留。报告先完整校验与计算（含全部批次的更正），再通过同目录临时文件原子硬链接新建；任何一批出错都不会留下部分报告。
